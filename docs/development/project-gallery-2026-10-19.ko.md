# 앱 중심 프로젝트 갤러리

기존 프로젝트·OTA·Runner API와 페이지 경로를 유지한 화면 개선입니다. 데이터베이스 마이그레이션, 설정 교체, 키 발급, 배포 이력 수정은 없습니다.

- 등록된 앱은 반응형 3열/2열/1열 카드로 표시합니다.
- iOS·Android 게시 상태와 SDK 보고 설치 기준 적용률을 분리합니다. 기기 보고가 없으면 적용 성공으로 추정하지 않습니다.
- 누적 다운로드·적용·재시작·실패·복구 수치와 환경 구분은 카드의 보고 영역에 보존합니다. 문제·해결된 기기·Runner 이력 링크도 유지합니다.
- 검색·상태 필터·보고 펼침은 클라이언트에서 처리합니다. 프로젝트 목록은 기존의 한 번에 집계하는 `/api/projects`와 기존 캐시·갱신 정책을 사용합니다. 앱별 조회를 추가하지 않습니다.
- Cloudflare 계정 전체 D1 사용량은 목록 아래의 접힌 인프라 영역에 표시합니다. 오래된 측정값의 경고와 측정 시각은 유지하며, Flora 자체의 프로젝트 등록 제한으로 표현하지 않습니다.

## 설치별 앱 아이콘

오픈소스 기본 소스에는 특정 운영자의 앱 이미지나 저장소 이름을 포함하지 않습니다. 기본값은 앱 이름의 첫 글자입니다. 설치별 공개 이미지가 있으면 빌드 후 **배포용 자산 디렉터리**에 다음 내용을 추가할 수 있습니다.

```js
// project-branding.js — 자격증명이나 개인키를 넣지 마세요.
export const projectBranding = Object.freeze({
  "example/mobile": "/project-icons/mobile.png"
});
```

같은 배포용 디렉터리의 `project-icons/mobile.png`를 함께 보관합니다. PNG·WebP·JPG만 지원하며 외부 URL·상위 경로·SVG는 허용하지 않습니다. 이미지가 없거나 로딩에 실패하면 앱 이름으로 돌아갑니다. 128~256px 정사각형 이미지를 권장합니다. GitHub 개인키나 설치 토큰을 이미지 URL에 넣으면 안 됩니다.

일반 화면과 마찬가지로 아이콘과 브랜딩 모듈도 기존 소유자 인증을 거쳐 제공됩니다. 새 데이터 조회 API나 DB 테이블은 만들지 않습니다. 정적 자산 요청은 기존 인증 경계를 사용합니다.

## 검증 범위

`project-ui.test.ts`, `admin-navigation.test.ts`, `admin-http.test.ts`, `build.test.ts`에서 앱별 정보 분리·안전한 아이콘 경로·인프라 펼침 상태·집계 조회 수·실패 이력·라우팅을 검증합니다. 보고 영역 클릭이 카드 선택으로 전파돼 추가 상태 조회를 만들지 않는 회귀 테스트를 포함합니다.

시각 검증은 운영 서버에서 읽은 있소·우리만나·Reward·QA 두 앱의 표시 정보를 사용한 **읽기 전용 로컬 미리보기**입니다. 운영 서버 쓰기와 신규 OTA 배포·실기기 적용 검증을 의미하지 않습니다. Cloudflare 운영 반영은 별도 배포 단계입니다.
