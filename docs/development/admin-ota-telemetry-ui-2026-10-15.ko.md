# 관리자 OTA 적용률·실패·복구 표시 점검

## 운영에서 발견한 문제와 수정

최신 배포를 보여 주는 `/api/projects`에는 SDK 적용률과 운영자 검증이 연결돼 있었으나, `/api/apps/:appId/operations`의 과거 배포에는 연결되지 않았다. 따라서 새 배포 이후에도 보존된 과거 실패·복구 기록을 OTA 이력 화면이 `사용자 적용 보고 미수집`으로 표시할 수 있었다. 기록 삭제나 SDK 미보고와 다른, 조회 응답의 누락 문제다.

인증된 기존 운영 조회에 이미 포함된 최근 배포 최대 20건만 대상으로 SDK 집계와 운영자 검증을 연결했다. 앱 ID와 현재 세션 권한을 확인하고 `[appId, deploymentId]` 키로 결합한다. 기존 D1 조회에 추가 요청·쓰기·마이그레이션은 없다. 기존 Durable Object에서 운영자 검증 1회와 SDK 2회의 인덱스 조인을 추가한다. 미보고 배포의 적용률을 만들어내지 않는다.

OTA 이력의 각 배포에서는 해당 배포의 실패 원인을 모두 보여 주도록 수정했다. 이전에는 두 원인 중 하나만 보여 주고 같은 앱 상세로 이동하라는 안내를 표시했으므로, 과거 Reward의 두 번째 원인을 확인하기 어려웠다. 목록의 최신 배포 카드 요약 방식은 유지한다.

## 보존과 조회량

배포 전후 API를 비교해 기존 배포 원본 42건(15·15·12), 자산, 탐지, GitHub 연결, 자동 작업, 정책, Runner 등록, 키 메타데이터와 접근/교체 이력이 동일함을 확인했다. 응답에 새로 추가한 `telemetry`·`verification` 필드만 제외해 배포 원본을 비교했다. 최신 iOS·Android 요약도 동일하다. 실제 SDK 보고나 운영자 검증 기록을 이번 화면 점검에서 대신 생성하지 않았다.

기존 D1·Durable Object namespace와 12개 바인딩, 호환 날짜/플래그와 사용 모델이 동일하다. 비밀값은 배포 설정에 기록하지 않고 기존 값을 유지했다. 요금제·인증 정책·EAS·Actions·PC Runner·자동 새로고침 정책을 바꾸지 않았다.

관리자 목록의 기존 60초 요약 캐시와 숨겨진 화면의 조회 중단은 유지한다. 운영 조회의 기존 D1 요청 10회(원래 5개 조회와 각 권한 확인)를 실제 workerd 테스트에서 확인했다. 이 수정은 그 수를 늘리지 않는다. 운영 웹 파일 10개를 빌드 소스와 대조했고 변경된 정적 파일은 의도한 `project-views.js` 하나다. HTML은 기존 Cloudflare beacon 삽입 부분만 제외해 대조했다.

## 코드 검증

- 새 실제 workerd HTTP 회귀: 이전 실패·복구와 새 미보고 배포 분리, 원본 필드 보존, 대상 20건 제한, 앱·소유자 격리, 미인증/폐기된 세션 차단, 외부 앱을 가리키는 잘못된 원본 행 차단, D1 조회 증가 없음.
- 과거 이력의 두 실패 원인 표시 테스트는 수정 전 두 번째 원인이 없어 실패했고, 수정 후 통과했다.
- 관련 HTTP·SDK 프로토콜·화면 테스트 29/29 통과, 전체 TypeScript 검사·Cloudflare 빌드·Wrangler dry run·변경 파일 공백 검사 통과.
