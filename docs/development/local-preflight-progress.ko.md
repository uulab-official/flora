# 로컬 빌드 실행 전 점검과 진행 관측

## 실행 전 점검
콘솔에서 대기 작업의 등록 설정을 선택하고 **빌드 실행 → 실행 전 점검**을 누릅니다. 작업 버전, 앱/저장소/Runner/플랫폼 연결, 체크아웃 권한, 실행 파일과 Git 사용 가능 여부, 이전 산출물, 체크아웃 잠금, 실제 커밋과 미커밋 변경을 검사합니다. 모든 필수 항목이 통과한 경우에만 화면의 실행 확인 버튼이 활성화됩니다.

점검은 작업 상태·SQLite 내용·Runner 잠금을 변경하지 않고 빌드 명령을 실행하지 않습니다. 운영자가 지정한 Git 도구로 `rev-parse`와 `status`를 실행합니다. 이 도구는 운영자가 신뢰해야 하며 임의 바이너리의 부작용을 격리하는 샌드박스는 아닙니다. 검사 실패와 의존 조건 때문에 미검사한 항목은 구분합니다.

점검 통과는 실행 예약/인증/실제 SDK 준비/코드 서명 증거가 아닙니다. 실제 실행 직전에 동일 조건과 원장 버전을 다시 검사합니다. 점검과 실행 사이에 소스가 바뀌거나 다른 Runner가 먼저 작업을 가져가면 실행을 거부합니다. 기존 출력이나 잠금을 자동 삭제하지 않습니다.

### CLI
```sh
node scripts/artifacts/build-ops.mjs preflight \
  --state-dir /ABSOLUTE/PRIVATE/STATE \
  --app app-a --job android-preview-001 \
  --recipe /ABSOLUTE/PRIVATE/recipe.json --expected-version 2
```
`expected-version`은 현재 작업 버전입니다. 레시피 파일은 소유자 전용(0600)이어야 합니다. 결과 JSON의 `ok`, `ready`, `checks`를 확인합니다. 통과는 종료 코드 0, 실패/미준비는 1입니다. 누락된 상태 디렉터리를 생성하지 않습니다.

HTTP 경로는 인증된 `POST /api/jobs/:app/:job/preflight`입니다. 입력은 `presetId`, `expectedVersion` 두 항목만 받습니다. 기존 세션·CSRF·Origin·Host·앱 허용 목록 검사를 적용하며 동시에 한 검사, 시작 후 2초 간격으로 제한합니다. 결과 반환 직전 세션을 다시 검사합니다. 임의 명령·경로 입력이나 웹 실행 비활성화 우회는 없습니다.

## 진행 관측
진행 패널에는 고정 단계(조건 점검, 소스 확인, 프로세스 실행, 파일 검증, 등록, 처리 종료), 경과 시간, stdout/stderr 출력 바이트 합계, 출력 상한, 마지막 출력 시각과 관측 시각만 표시합니다. 원문 로그·환경변수·경로·명령 인자·PID는 전달하지 않습니다. 진행률 백분율을 추정하지 않습니다.

실행 중 heartbeat는 1초마다 갱신하고 데이터 관측은 최대 초당 약 4회로 제한합니다. 웹은 기존 3초/15초 폴링을 사용합니다. 출력 없는 실행의 경과 시간도 갱신하지만, 출력이 없다는 이유로 멈췄다고 판정하지 않습니다. 카운터는 현재 콘솔 프로세스의 메모리 관측이며 재시작 후 복원하지 않습니다. `finished`는 관측 종료를 뜻하며 실제 성공/실패/취소는 작업 상태를 확인해야 합니다.

네 단계(`runner-process-starting`, `runner-process-exited`, `runner-artifact-verifying`, `runner-artifact-publishing`)는 기존 audit 테이블에 저장합니다. 동일 Runner·작업 버전의 실행 중 작업에만 순서대로 기록하고 중복을 무시합니다. heartbeat마다 DB를 쓰지 않으며 작업 버전을 소모하지 않습니다. 백업·검증·복원 뒤에도 이력은 유지됩니다. 이 기록만으로 재시작 후 프로세스 생존을 증명하지 않습니다.

## 출력 제한
기본 합산 출력 상한은 이전과 같은 262144바이트(256 KiB)입니다. 출력이 많은 신뢰하는 빌드는 운영자가 레시피에 `outputLimitBytes`를 지정할 수 있습니다.

```json
{ "outputLimitBytes": 8388608 }
```
위 항목은 기존 레시피에 추가하는 값이며 단독 레시피가 아닙니다. 허용 범위는 1024~67108864바이트(64 MiB)입니다. 무제한은 허용하지 않고 상한 초과 시 실제 프로세스를 종료한 뒤 실패를 기록합니다. 원문 로그는 상한을 늘려도 저장하지 않습니다.

## 중지·정합성
프로세스 종료 후 파일 검증 중 도착한 중지 신호는 등록 시작 전 다시 확인합니다. 중지된 작업을 무조건 성공으로 게시하지 않습니다. 최종 저장이 이미 시작된 뒤 요청은 저장과 경합할 수 있으므로 최종 원장 상태를 확인해야 합니다. 다른 Runner가 변경한 버전을 덮어쓰지 않습니다.

출력 폴더가 심볼릭 링크로 외부를 가리키는 경우도 사전에 거부합니다. 이 검사는 운영자만 수정 가능한 신뢰하는 작업 폴더를 전제로 하며 공격자가 동시에 경로를 바꾸는 환경을 격리하지 않습니다.

## 검증 경계
관련 단위/실제 Git·HTTP·하위 프로세스·SQLite·백업 복원 테스트와 합성 브라우저 컴포넌트 테스트를 구분합니다. 브라우저 localhost 탐색은 관리 정책에 막혀 우회하지 않았습니다. Native Gradle/Xcode, 서명, 기기 설치, Hosted UI/OTA Runner 통합, 외부 Provider는 이 변경의 검증 범위가 아닙니다. 운영 Worker/D1/OTA와 main은 변경하지 않습니다.
