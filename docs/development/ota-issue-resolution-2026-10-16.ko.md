# OTA 문제의 미복구·해결됨 분류 — 2026-10-16

프로젝트 목록의 **OTA 미복구 문제**는 최근 iOS·Android 배포에서 아직 정상 적용·재시작이 확인되지 않은 설치만 찾는다. **OTA 해결됨**에서는 복구가 확인된 설치의 기존 실패 기록으로 이동한다. `확인 필요`에는 미복구 OTA와 자동 배포가 켜진 앱의 Runner 연결 문제를 포함하며, 해결된 OTA만 있는 앱은 제외한다. 이름·저장소 검색과 상태 조건은 함께 적용된다.

## 판정 기준

- 같은 앱·배포·익명 설치의 가장 늦은 `failed` 또는 `rolled_back` 시각을 기준으로 한다. 일반 실패와 네이티브 자동 복구가 같은 설치에 있어도 문제 설치는 한 번만 센다.
- 그 실패보다 **엄격히 나중인 실행 확인과 재시작 확인이 모두** 있어야 해결됨이다. 동일 시각, 다운로드만 성공, 다른 설치의 성공은 해결 근거가 아니다.
- 복구 뒤 새 실패가 발생하면 다시 미복구로 돌아간다. 보고 도착 순서와 중복 전송은 판정을 바꾸지 않는다.
- 기존 `recoveredInstallations`는 과거 누적 복구 통계로 유지한다. 누적 실패에서 누적 복구를 빼서 현재 문제 수를 만들지 않는다. 서버의 자동 롤백 취소도 특정 설치의 복구로 취급하지 않는다.
- 상세 이벤트가 완전한 과거 기록은 마지막 실패 시각을 재구성한다. 불완전한 기록은 저장된 실패 집계의 시각 상한보다 두 확인이 모두 늦을 때만 복구를 인정한다. 근거가 부족하면 **복구 시점 미확인**으로 미복구에 포함한다. 과거 이벤트를 만들어 넣지 않는다.

이 상태는 SDK가 보고한 **해당 배포의 설치 결과**다. 전체 기기의 실시간 장애 유무나 현재 실행 중인 모든 버전을 나타내지는 않는다. 이전 정상 번들로 네이티브 복귀한 기록도 실패한 배포 자체가 같은 설치에서 정상 실행됐다는 뜻은 아니다. 프로젝트 목록은 플랫폼별 최근 배포만 요약하며, 오래된 배포는 OTA 이력에서 연다.

## 화면과 접근

배포 상세는 `전체 설치`, `미복구`, `해결됨`, `문제 이력`으로 나눈다. `문제 이력`에는 복구된 실패도 남긴다. 현재 상태와 과거 누적 플래그를 함께 보여주며 원래 실패 원인과 이벤트는 지우지 않는다.

- `/apps/{appId}/ota/{deploymentId}/unresolved`
- `/apps/{appId}/ota/{deploymentId}/resolved`
- 기존 기본 상세 및 `/issues` 경로도 유지한다.

로그인 복귀 경로, 앱·배포·필터별 목록 커서와 캐시를 분리한다. 다른 범위의 커서는 D1 조회 전에 거절한다. 새 필터 화면은 첫 설치의 이벤트만 한 번 열고, 기본 전체 화면은 선택할 때만 이벤트를 읽는다.

## 데이터와 조회량

기존 DO에 `flora_sdk_telemetry_issue_state`와 `flora_sdk_telemetry_issue_aggregates` 및 상태별 페이지 인덱스를 추가한다. 최초 한 번 기존 설치·실패·보관 이벤트를 읽어 별도 분류를 채운다. 기존 설치 JSON·누적 집계·원본 이벤트는 재작성하지 않는다. 초기화와 완료 마커는 동기 트랜잭션으로 함께 기록한다. 설치 20,000개·보관 이벤트 50,000개인 기존 상한을 유지한다.

이후 새 SDK 보고의 분류 갱신은 원래 보고 트랜잭션 안에서 해당 설치만 처리한다. 프로젝트 요약은 기존 두 번의 인덱스 기반 DO 집계 조회에 새 집계를 조인한다. 앱별 추가 API나 반복 전체 설치 스캔은 없다. 상세는 최대 20개 설치의 상태를 조인하며 기존 페이지당 D1 범위 확인 2회를 유지한다.

검색·필터 변경은 추가 API 0회다. 프로젝트·개요 화면의 기존 60초 요약 확인과 수동 새로고침을 유지하며 새 폴링이나 타이머를 추가하지 않는다. 배포 기기 상세는 기존처럼 자동 조회하지 않는다. 초기 분류와 새 상태 저장에는 DO 쓰기가 발생하며 무료 한도 자체를 우회하는 기능은 아니다.

## 검증 범위

로컬 HTTP 통합 테스트는 Isso·Promise·Reward × iOS·Android 여섯 범위에서 실패 → 복구 → 재실패 → 재복구, 앱별 참조 격리, 원본 배포 보존과 페이지당 D1 2회를 확인한다. 별도 저장소 테스트는 중복·역순·동시각·두 실패 종류의 중복, 다른 설치의 성공, 과거 기록의 불확실성, 이관 실패와 보고 관찰자 실패의 원자성, 반복 조회의 무스캔, 상태별 페이지·커서 분리를 검증한다.

관리 화면 검증에서는 운영에 이미 수집된 실제 앱 SDK 기록을 사용한다. 새 실패 이벤트를 운영 API에 임의 전송하거나 기존 기기 보호 상태를 초기화하지 않는다. 이 변경으로 새 네이티브 빌드를 만들거나 OTA를 추가 게시하지 않는다.
