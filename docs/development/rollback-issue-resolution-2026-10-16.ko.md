# 롤백 복구와 원래 OTA 문제 연결 검증

검증일: 2026-10-16. 운영 주소: https://flora.uulab.co.kr/projects

후속 보강: [롤백 재실패와 재복구 검증](rollback-relapse-2026-10-16.ko.md)에서 여러 단계의 롤백 계보와 재발 상태 전환까지 확장했다. 아래 직접 연결 범위는 당시 버전의 검증 기록이다.

## 운영 화면에서 확인하기

프로젝트 목록의 `미복구`는 아직 정상 복구가 확인되지 않은 OTA 문제를 표시한다. `해결됨`에서는 원래 문제의 기기 이력으로 이동할 수 있다. 최신 배포가 롤백 배포여도 연결된 원래 문제의 상태를 함께 확인한다.

같은 설치에서 연결된 롤백 배포의 적용 실행과 재시작이 모두 확인되면 원래 문제를 `롤백으로 해결됨`으로 표시한다. 원래 문제 상세의 `정상 복구된 롤백 배포 이력` 링크는 실제 복구를 보고한 배포로 이동한다. 롤백 배포 자체의 문제 이력과 원래 문제 이력은 서로 다른 이름과 링크로 구분한다.

원래 실패 배포의 적용·재시작 성공 여부나 누적 통계를 바꾸지 않는다. 예를 들어 원래 문제 기기의 `적용 미확인`, `재시작 미확인`은 유지하면서, 별도 복구 근거에 롤백 적용·재시작 확인 시각을 표시한다. 서로 다른 배포의 설치 수를 더하지 않는다.

## 복구 판정과 오탐 방지

- 서버가 D1의 원본 배포 세 건을 조회해 롤백 배포, 원래 문제 배포, 정상 복구 원본의 연결과 게시 순서를 검증한다.
- 소유자·앱·플랫폼·채널·런타임이 모두 같아야 한다. SDK가 보내는 임의의 연결 정보나 기존 티켓의 롤백 여부만으로는 인정하지 않는다.
- 배포별 화면 익명 식별자는 유지하되 서버 내부의 앱 범위 설치 식별값으로 같은 설치인지 검증한다.
- 롤백의 적용 실행 확인과 재시작 확인이 모두 원래 문제의 마지막 실패, 롤백 게시, 관련 롤백 실패보다 엄격히 나중이어야 한다.
- 게시·세션 발급·다운로드·다른 설치의 성공·한쪽 확인만으로 해결하지 않는다. 같은 시각, 과거 보고의 재전송, 도착 순서 변경으로 해결 상태를 만들지 않는다.
- 원래 배포나 관련 롤백에서 다시 실패하면 원래 문제를 재개한다. 이후 새로운 적용·재시작 확인 쌍이 있어야 다시 해결한다.
- 연결 근거와 집계를 트랜잭션으로 갱신한다. 기존 원시 보고·이벤트 이력은 수정하지 않는다.

이번 연결은 직접적인 `원래 배포 → 롤백 배포` 관계를 대상으로 한다. 여러 단계의 롤백을 거슬러 올라가는 전이적 복구 판정은 검증 범위에 포함하지 않았다.

## 조회량

프로젝트 요약은 현재 배포와 연결된 원래 배포의 집계를 한 번에 읽는다. 최대 100개 앱, 두 플랫폼, 현재·원래 배포에 해당하는 400개 대상을 제한된 배치로 처리한다. 별도의 프런트엔드 API나 타이머를 추가하지 않았다.

상세 화면의 D1 호출은 기존과 같이 두 번이다. 기존 롤백 계보를 최초 접근 시 제한된 조회에 포함해 저장하므로, 이전에 수신한 SDK 보고도 재전송 없이 연결할 수 있다. 운영 이력의 페이지 구성이 바뀌면 앱 인덱스를 사용하는 제한된 계보 조회를 한 번 수행하고 워터마크를 저장한다.

HTTP 회귀 테스트 기준 운영 이력의 최초 조회는 D1 11회, 같은 워터마크의 후속 조회는 10회다. 계보 조회는 각각 1회와 0회다. SDK 보고 수신·중복 수신과 유휴 알람은 D1 조회 0회를 유지했다. 실제 UI의 검색·필터 변경은 API 호출 0회, 배포 상세의 65초 유휴 관찰도 API 호출 0회였다. 프로젝트 목록의 기존 주기적 새로고침은 유지한다.

## 실제 설치 앱 검증

여섯 배포 모두 SDK 집계에서 다운로드 1, 적용 실행 1, 재시작 1을 확인했다. 원래 문제는 각각 미복구 0, 해결됨 1, 롤백으로 해결됨 1이다. 원래 실패 설치의 적용·재시작 플래그는 변경되지 않았다. iOS 보고는 새 백엔드 배포 전에 생성되어 기존 보고의 연결을 검증했고, Android 보고는 백엔드 준비 확인 후 생성되어 실시간 연결을 검증했다.

실서비스 브라우저에서 여섯 원래 문제의 해결됨 화면과 연결된 롤백 배포의 다운로드·적용·재시작 화면을 직접 확인했다. 최종 목록은 전체 앱 3, OTA 미복구 앱 0, 해결됨 앱 3이다. iOS만 복구된 중간 상태에서는 Android 미복구와 iOS 해결됨을 동시에 표시하는 것도 확인했다. 390px 모바일 화면에 가로 넘침이나 중첩된 링크·버튼이 없었다.

Reward는 기존 8초 시작 정책을 유지했다. 첫 실행에서 내려받은 캐시를 이후 정상 실행에서 적용했으므로 최초 다운로드 실행에서 즉시 적용했다고 주장하지 않는다. Isso Android에서는 실제 다운로드 단계 `NATIVE_OPERATION_FAILED`가 발생했고, 데이터 보존 상태로 재시도·적용·재시작 후 복구됐다. 그 실패와 복구 이력도 유지했다. 최초 대기 지연의 근본 원인을 확정하거나 수정했다고 주장하지 않는다.

최초 백엔드 배포 직후 일부 조회에서 이전 형식이 관찰됐다. 이 관찰도 보관하고, 새 계보 메타데이터와 iOS 복구 연결이 나타난 뒤 Android 검증을 진행했다. 원인을 단정하거나 보고를 조작·재게시하지 않았다.

## 데이터 보존과 배포

- D1 기존 배포 96건의 소유자·앱·ID·원문 JSON이 전부 동일하다. 새 롤백 여섯 건만 추가되어 총 102건이다.
- 세 앱의 기존 원본 SDK 보고, 자산, 저장소 연결, 탐지 결과, 앱 설정, 자동화 정책·작업, 소스 스냅샷·이력, 키·접근 이력, 자동 롤백 정책·판단 이력을 대조했다.
- 여섯 설치의 실행 바이너리·내장 번들 또는 APK, 앱 데이터 표식 해시가 동일하다. 기존 차단된 OTA 목록도 유지했다.
- Cloudflare의 기존 12개 연결 리소스가 동일하다. 새 유료 자원이나 요금제 변경은 없다. PC Runner는 기존 서비스로 실행 중이다.
- 최종 Worker 버전: `8b987093-ca07-40ec-9ab9-d87c9c3e8286`, 트래픽 100%. 운영 HTML과 두 변경 JS 파일의 해시가 최종 빌드와 일치한다.

## 검증 자료

신규 롤백 연결 통합 테스트는 같은 설치 확인, 여섯 앱·플랫폼 조합, 오탐·재발·재시도, 최초 상세 조회의 기존 보고 연결, 마이그레이션과 실패 트랜잭션 분리를 검증한다. 프로젝트·상세 UI 테스트는 원래 성공 통계를 보존하는 롤백 해결, 혼합 상태, 잘못된 범위, 문맥별 링크를 검증한다.

전체 회귀 실행은 1,270건 중 1,266건 통과, 조건부 3건 제외, 기존 조회 예산 단언 1건 실패였다. 그 1건은 최초 동기화 11회·후속 10회 및 계보 조회 1회·0회를 확인하도록 수정한 뒤 별도 재실행에서 통과했다. 이 테스트 수정 뒤 전체 21분 실행을 다시 반복하지는 않았다. 앞선 자동 롤백 HTTP 조회 예산 테스트도 같은 기준으로 수정했고 해당 파일 12건이 통과했다. SDK·유휴 조회 0회 검증은 유지했다. 신규 롤백 연결 통합 테스트 9건과 프런트엔드 검증, 최종 타입 검사도 통과했다.

전체 실행 원본은 `dist/rollback-issue-resolution-2026-10-16/evidence/full-tests.log`, 마지막 실패 테스트의 수정 후 결과는 같은 폴더의 `history-final.log`, 타입 검사는 `typecheck-final.log`에 보관한다. 전체 실행 로그의 실패 흔적을 덮어쓰지 않았다.

비공개 원본 증거는 `dist/rollback-issue-resolution-2026-10-16/evidence/`, 운영 UI 캡처는 `output/playwright/rollback-issue-resolution-2026-10-16/`에 있다. 세션·개인키·SDK 티켓은 문서에 포함하지 않는다.
