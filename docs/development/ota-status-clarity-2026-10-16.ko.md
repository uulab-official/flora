# OTA 운영 화면의 실패·복구 표시 보강 — 2026-10-16

Flora의 OTA 배포 상세, OTA 목록, 프로젝트 목록과 앱 개요에서 일반 실패 보고·네이티브 자동 복구·같은 설치의 실패 후 정상 실행을 구분했다. 서버 집계나 기존 보고를 수정하지 않고 화면이 누락하거나 혼동하던 의미를 바로잡았다.

## 바뀐 동작

기존 상세 요약은 `일반 실패 0 · 네이티브 자동 복구 1 · 동일 설치 복구 0`인 유효한 사례를 **실패 0 · 복구 0**으로만 표시했다. 네이티브 복구 집계를 생략했기 때문이다. 이제 다음 여덟 항목을 함께 표시한다.

- 보고 설치 수와 SDK 보고 설치 기준 누적 적용률
- 다운로드 확인, 적용 실행 확인, 재시작 확인
- 일반 실패 보고, 네이티브 자동 복구, 동일 설치 복구

데스크톱은 네 열, 작은 화면은 두 열로 배치한다. 설치별 설명도 네이티브의 이전 번들 복귀와 해당 배포의 정상 실행을 구분한다. 과거 보고에 복구 집계가 없는 경우에는 미확인으로 표시하고, 소급해서 복구 수를 만들어 넣지 않는다. 기존 서버가 구형 저장 값을 0으로 정규화하는 경우도 있으므로 과거 미보고 복구가 0이라는 뜻으로 해석하지 않는다.

OTA 목록에서는 자동 롤백 취소를 단순 ‘실행 건너뜀’ 대신 **실패 기준 미충족으로 취소**로 표시한다. 최초 감지와 취소 시 재확인 수치를 나눠 보여주며, 별도 설치의 정상 실행을 최초 실패 설치의 복구라고 표시하지 않는다. 취소 시 스냅샷이 없는 과거 기록에는 재확인 수치를 만들어 넣지 않는다.

자동 롤백 판단의 실패율·정상 실행 수는 소유자가 판단에 허용한 설치 기준이다. SDK 누적 현황은 허용하지 않은 설치의 보고도 포함할 수 있다. 각 실패·복구 수치는 겹칠 수 있으므로 합산하지 않는다. 실패 원인 목록에는 일반 실패와 네이티브 복구 이벤트의 원인이 함께 포함되며, 실제 이벤트 종류와 시각은 설치 상세에서 확인한다.
