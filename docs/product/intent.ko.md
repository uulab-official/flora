# Flora를 만드는 이유

작성일: 2026-10-06 · 제품명: Flora(임시)

## 원하는 개발의 취지

앱을 여러 개 운영하다 보면 개발보다 배포와 설정 관리에 시간을 쓰게 된다. GitHub, Expo, App Store Connect, Play Console, Firebase, Cloudflare, 광고·오류 대시보드를 오가고, 인증서와 `.env` 파일을 찾아 사람에게 전달해야 한다.

Flora에서는 앱을 선택하면 현재 사용자에게 어떤 버전이 나가 있는지, 어떤 커밋과 설정으로 빌드했는지, 누가 무엇을 배포했는지 한곳에서 알 수 있어야 한다. 필요한 외부 서비스는 플러그인처럼 연결한다. 운영자는 각 도구의 세부 절차를 매번 기억하지 않아도 된다.

Expo의 프레임워크와 공개 도구는 계속 활용한다. 빌드·스토어 전송·OTA·웹 배포를 위해 Expo 유료 플랜을 필수로 구독하지 않아도 되는 독립적인 실행 경로를 만든다. 기존 Expo 서비스 연결은 선택 사항으로 남긴다.

## 가장 중요한 추가 요구: 다른 PC에서도 되어야 한다

“내 PC에서만 된다”면 성공이 아니다. 다음이 제품의 기본 동작이어야 한다.

1. 프로젝트 설정·소스 참조·인증서 버전·권한·배포 이력은 조직 소유다
2. 개발자는 어느 PC의 브라우저에서든 로그인해서 허용된 작업을 요청한다
3. 작업은 특정 개인의 PC가 아니라 조건에 맞는 조직 Runner에서 실행된다
4. 새 PC에는 Runner와 필요한 도구를 준비하고 조직에 등록하면 된다
5. 기존 PC가 꺼졌을 때 다른 호환 Runner가 있으면 안전하게 새 시도로 이어간다
6. 호환 Runner가 없으면 “대기 중 / 필요한 환경”을 명확히 보여준다. 가짜 성공이나 무한 진행 표시를 하지 않는다
7. 배포 권한이 없는 사람은 코드 작업을 할 수 있어도 production 변경은 할 수 없다

즉 **개발자가 작업을 요청하는 컴퓨터와 실제 빌드하는 컴퓨터를 분리**한다. iOS를 Windows에서 직접 컴파일한다는 약속은 하지 않는다. Windows 사용자가 조직 Mac Runner로 배포를 요청하는 경험을 제공한다.

## 양보하지 않을 원칙

- **완전 오픈소스:** 조직·권한·보안·Self-host까지 핵심 기능을 공개한다
- **Cloudflare 우선:** 우리 서비스도 Workers/D1/R2 등을 이용해 배포한다
- **플러그인 연동:** GitHub·Apple·Google·Expo·Firebase·Cloudflare 등을 계약된 인터페이스로 연결한다
- **사용자 인프라 활용:** 빌드 비용을 서비스가 모두 떠안지 않는다
- **PC 독립성:** 개인 Keychain, 전역 npm 설정, 절대 경로, 개인 로그인 세션이 숨은 필수 조건이 되면 안 된다
- **하나의 이력:** Release에서 소스·설정·서명·바이너리·OTA·웹·스토어 상태를 추적한다
- **정직한 상태:** 계획, 개발 중, 검증됨, 실제 배포됨을 구분한다
- **이름 변경 가능:** Flora는 표시 이름이며 DB와 Core에 브랜드를 박지 않는다

## 첫 성공 장면

다른 개발자가 새 PC에서 조직에 가입한다. GitHub에 연결된 Expo 앱을 선택하고 production 빌드를 요청한다. 권한과 승인 조건을 통과하면 공용 Runner가 정확한 커밋과 설정 스냅샷을 받아 빌드한다. 필요한 인증서는 해당 Job 동안만 전달된다. 결과는 TestFlight, Play, OTA, Web에 각각 연결되고 하나의 Release 타임라인에서 확인된다.

첫 PC가 없어도 이 흐름을 재현할 수 있어야 한다. 기능 개수보다 이 한 가지 흐름의 신뢰성이 먼저다.

## 범위와 현실적인 기대

초기에는 GitHub → Runner → Config/Vault → Build → Store → OTA → Web → Release Timeline에 집중한다. Push, Links, 광고 수익, In-App, Analytics는 같은 기반의 모듈로 확장한다.

완전 오픈소스는 무료 클라우드 무제한 사용을 뜻하지 않는다. 외부 계정·하드웨어·사용량 비용을 투명하게 보여주고, 유료 EAS 없이도 관리할 수 있는 선택권을 제공한다. 지원되지 않는 Provider 기능은 제한과 대안을 그대로 표시한다.
